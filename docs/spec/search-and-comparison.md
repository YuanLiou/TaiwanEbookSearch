# 搜尋與比價

## 搜尋請求

`SEARCH-001` 使用者可輸入書名或 ISBN，透過鍵盤搜尋動作或搜尋按鈕開始搜尋。只含空白的輸入不得送出，並應提供可觀察的錯誤提示。

`SEARCH-002` 搜尋必須帶入目前啟用的書店清單，清單順序由使用者設定決定。停用來源不得送入本次 API 請求。

`SEARCH-003` 若搜尋字串與前一次請求或目前顯示結果的搜尋字串完全相同，App 必須忽略這次請求，不重新呼叫 API，也不額外顯示提示。比對是完整字串比對，不先正規化大小寫或前後空白。此規則只約束畫面搜尋。系統 agent 入口見 `APPFN-003`。

`SEARCH-004` 新請求進入時，若舊網路請求仍在執行，App 必須取消舊請求、清除舊結果並以最新請求為準。舊請求不得覆蓋新結果。載入期間目前會停用一般搜尋與相機按鈕。

`SEARCH-005` App 必須先確認裝置有可用網路。無網路時不得送出請求或寫入一般搜尋紀錄。

## API 排序契約

`SEARCH-006` API 對每家書店的結果依相關性排列。第一筆是該書店最可能符合搜尋條件的候選商品，但不保證就是使用者真正要找的書。

`SEARCH-007` App 必須取每個已啟用且有結果來源的第一筆，彙整成「最佳結果」，再依 API 提供的價格數值由低到高排列。

`SEARCH-008` 每個書店自己的區段必須排除已進入「最佳結果」的第一筆，只取 API 排名第 2 至第 11 筆，最多 10 筆，再依使用者偏好排序。

`SEARCH-009` 書店區段的預設排序是價格數值由低到高。使用者關閉「依價格排序」後，改以 App 計算的書名相關性由高到低排列。「最佳結果」永遠依價格數值排序，不受此設定影響。

`SEARCH-010` 書店區段的顯示順序必須遵循使用者保存的書店順序。停用來源不顯示區段。

## 部分成功

`SEARCH-011` 單一書店失敗、離線或沒有結果時，不得丟棄其他書店的成功結果。App 必須允許部分成功，並在對應來源區段顯示其服務異常、搜尋失敗訊息或無結果狀態。

`SEARCH-012` 整體請求錯誤至少區分無網路、連線逾時與一般網路錯誤。規格要求使用者能觀察到錯誤，不綁定必須使用 Dialog、Toast 或特定 UI 元件。

## 結果資料

`SEARCH-013` 一筆可用商品結果的基本資料包含書名、來源與商品連結。價格與幣別由 API 提供，價格可以未知；作者、封面與簡介可以缺少。缺少選填資料時不得移除整筆結果。

`SEARCH-014` App 顯示 API 提供的價格與幣別，不進行匯率換算，也不自行推斷跨幣別的真實價差。

`SEARCH-015` 點擊商品結果後的導流不得在 App 內完成付款或購買。詳細行為見 [navigation-sharing-deep-links.md](navigation-sharing-deep-links.md)。

## 搜尋紀錄時機

`SEARCH-016` 一般搜尋在 API 回應前保存搜尋字串。因此已送出的請求即使逾時、失敗或沒有結果，仍保留紀錄；無網路而未送出的請求不保存。詳細紀錄規則見 [history-and-settings.md](history-and-settings.md)。

## 主要實作入口

目前主要入口是 `BookSearchActivity`、`BookSearchViewModel`、`GetBooksWithStoresUseCase`、`BookRepositoryImpl`、`BookStoresMapper` 與 `BookStoresSorter`。這些路徑用於調查，不是不可替換的實作契約。
